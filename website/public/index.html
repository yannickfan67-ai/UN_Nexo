WHY UN_NEXO

Less mystery.
More control.

A launcher should tell you what it is doing, what it changed and what failed.

01

Separated core

Launcher logic stays separate from the desktop UI so the project can evolve without turning into one monolith.

02

Visible state

Preparation, starting, running, failure and repair are explicit states instead of one endless loading indicator.

FAQ

Common questions.

Is UN_Nexo an official Minecraft launcher?

No. UN_Nexo is an independent project and is not approved by or associated with Mojang or Microsoft.

Does it support Microsoft accounts?

The public-client sign-in flow is implemented. Live Minecraft Services use still depends on Microsoft/Minecraft authorization and real-account acceptance testing.

Does UN_Nexo provide an offline launch mode?

No. Packaged builds require an authenticated Microsoft account and a valid Minecraft: Java Edition profile. Authentication or service failures do not fall back to an offline identity.

Does it support old Minecraft versions?

Current testing includes modern 1.21.4, legacy 1.8.9 and a real 1.5.2 path with pre-1.6 resource handling.

Where are logs and diagnostics?

Each instance keeps launcher logs and launch traces. Failed launches can also expose a sanitized diagnostic export workflow.

Where should bugs be reported?

Use the public GitHub issue tracker so failures, logs and fixes can stay attached to the project history.
